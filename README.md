# 循链 LoopLink · 工业废物资源化撮合平台

一个纯前端网页 Demo，解决工业废物回收里最麻烦的一环：**把「谁有废物」「谁能处理」「谁要再生料」三张互不相干的表对上**。

打开方式：双击 `index.html`。没有依赖、不需要构建、不联网。

---

## 快速开始

```bash
# 方式一：直接双击 index.html

# 方式二：起个静态服务
npx serve .

python -m http.server 8000
```

支持深链直达某个页面：


## 要解决的问题

废物回收不是「卖废品」这么简单。一条完整的资源化链路有三段，任何一段断了，废物就只能进填埋场：

```
供给方                加工厂                    需求方
工厂产生废物    →   分选 / 破碎 / 熔炼    →   买再生料做新产品
"我有 320 吨废纸"   "我收废纸，出再生纸浆"    "我要 320 吨再生纸浆"
```

难点在于三方的描述口径完全不同：供给方说**废物品类**，需求方说**产品品类**，中间没有天然对应关系。加工厂就是那个翻译器。

所以本平台的核心设计是：**要求加工厂同时登记「能吃什么」和「能产出什么、收率多少」**，用收率把废物量折算成再生品量，三段链路才能串起来。

## 撮合算法

### 分配流程

对每一条废物供给，按顺序执行：

1. **筛品类** —— 过滤出 `accepts` 包含该废物品类的加工厂
2. **扣产能** —— 用 `cap - load` 算出剩余产能，吃不完就分给下一家
3. **按收率折算** —— `产出量 = 承接量 × ratio`，一家厂可能产出多种再生品
4. **匹配需求** —— 拿每个产出物去找 `type` 完全一致、且还没被填满的需求方，按可接受单价从高到低分配
5. **打分** —— 对这一段链路（供给→某家加工厂）计算匹配度

这是一个**带产能消耗的贪心分配**：被吃掉多少产能就减多少，同一批废物可以拆给多家加工厂。

### 匹配度打分（满分 100）

| 维度 | 权重 | 说明 |
|---|---|---|
| 品类匹配 | 40 | `accepts` 命中的基础分 |
| 产能满足 | 20 | 剩余产能占待处理量的比例 |
| 产出被吸收 | 25 | 再生品中有多少被需求方认领 |
| 区域协同 | 8 | 同城 0.75、同区 1.0、跨市 0.4 |
| 加工厂评级 | 7 | 平台评分 / 5 |

一条供给的多段链路按承接量加权平均，得到该条废物的整体匹配度。

### 三种结果状态

- **链路闭环** —— 废物全部被承接，产出物全部被吸收
- **部分匹配** —— 只承接了一部分，或产出物有剩余
- **匹配失败** —— 没有加工厂能接收该品类

剩余的废物会标记为「未消纳」，无人认领的再生品标记为「待消纳」，两者都会进入总览页的**链路缺口诊断**，分别对应「该扩产」和「该招商」两类结论。

## 功能页面

### 平台总览
- 4 个 KPI：登记废物总量、撮合消纳量、再生品需求满足率、预估碳减排
- 按废物品类的**供给量 vs 加工余量**对比条形图，缺口处直接标注待消纳量
- 加工厂产能利用率排行（已有占用 + 撮合吃进两段式进度条）
- 链路缺口诊断 + 最近撮合动态

### 智能撮合
- 顶部四段漏斗：废物入池 → 撮合消纳 → 再生品产出 → 需求满足
- 每条结果一张卡片，画成 `供给方 → 加工厂 → 再生品 → 需求方` 的四段链路，左侧匹配度圆环
- 一家厂承接一部分时画多段链路；未消纳的废物在卡片底部单独标注
- 匹配度阈值滑块可实时过滤
- 支持导出撮合方案 CSV

### 三方登记
| 页面 | 登记内容 | 关键字段 |
|---|---|---|
| 供给方 | 废物从哪来、有多少、想卖多少钱 | 废物类型、月产出量、期望处置单价 |
| 加工厂 | 能吃什么、还剩多少产能、能产出什么 | 可接收类型（多选）、处理能力、已占用、**产出物 + 收率** |
| 需求方 | 要什么再生料、要多少、能出多少钱 | 需求产品类型、月需求量、可接受单价 |

提交后立即重新撮合，三方数据实时联动。

## 演示数据

内置南昌 / 赣江新区一套贴近真实的种子数据：10 家供给方、10 家加工厂、14 家需求方，覆盖 10 类废物（废纸、废塑料、废金属、废玻璃、废纺织品、废旧锂电池、废木材、餐厨垃圾、废橡胶、电子废弃物）。

初始状态跑出来的结果：

| 指标 | 数值 |
|---|---|
| 登记废物总量 | 1,418 吨/月 |
| 撮合消纳量 | 1,378 吨/月（撮合率 97.2%） |
| 再生品产出 | 1,117.5 吨/月 |
| 需求满足率 | 67.7% |
| 碳减排 | 4,476 tCO₂e |
| 预估成交额 | ¥8,463,133 |
| 未消纳废物 | 40 吨（废金属，区域产能见顶） |
| 待寻单再生品 | 69 吨（胶粉、擦机布等无下游） |

数据刻意留了缺口——洪城金属熔炼产能被打到 100%、有机肥只满足 21%，这样缺口诊断面板才有真实的结论可给。

改数据有两种方式：
- 页面上点「重置演示数据」恢复初始状态
- 直接改 `index.html` 里的 `SEED` 对象（`supplies` / `processors` / `demands`）

## 数据结构

```js
// 供给方
{ id, company, type, qty, price, city }

// 加工厂 —— outputs 是撮合的关键
{ id, name, city, rating, accepts: ['废纸'], cap, load,
  outputs: [{ type: '再生纸浆', ratio: 0.82 }, { type: '纸板', ratio: 0.10 }] }

// 需求方
{ id, company, type, qty, price, city }
```

`ratio`（收率）表示每吨废物能产出多少吨该再生品，取值 0~1。同一家加工厂可以有多个产出物，收率之和不要求等于 1（残渣、损耗不计入）。

**硬性约束**：加工厂 `outputs[].type` 必须与需求方 `type` 字符串完全一致才能匹配。这是有意为之——它迫使双方用同一套再生品命名，否则撮合永远对不上。

## 技术实现

- **单文件**：`index.html` 内联全部 HTML / CSS / JS，80 KB，零外部依赖，无 CDN、无框架、无图表库
- **状态管理**：纯内存 `state` 对象，重置靠 `clone(SEED)`，未使用 localStorage（演示场景下每次打开都是干净的）
- **图表**：全部手写 —— 条形图用 CSS 宽度百分比，匹配度圆环用 SVG `stroke-dasharray`
- **响应式**：≤860px 隐藏侧栏，切换为顶部横向胶囊导航；链路卡片自动转为纵向堆叠
- **碳减排估算**：按品类设定减排因子（废金属 9.5、电子废弃物 5.5、废旧锂电池 4.8、废纸 1.8 等 tCO₂e/吨），乘以撮合量

浏览器兼容：Chrome / Edge / Safari 现代版本。

## 已知限制

这些是 Demo 的刻意取舍，上生产前需要替换：

1. **撮合是贪心的，不是全局最优**
   按供给登记顺序逐条分配，先登记的废物优先吃掉优质产能。真实场景需要建整数规划模型（OR-Tools / 匈牙利算法），以总物流成本或总碳减排为目标函数求解。

2. **没有考虑时间维度**
   所有数据都按「吨/月」静态处理，没有库存、没有提货周期、没有合同周期。

3. **没有真实性校验**
   谁都能登记任意产能，平台没有资质核验、没有危废经营许可证校验。

4. **数据不持久**
   刷新即重置。接入后端的话需要用户体系 + 三张业务表 + 撮合结果快照表。

5. **碳减排因子是行业经验值**
   不是按具体工艺和区域电网排放因子测算的，仅用于展示量级。
