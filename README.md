# 循链 LoopLink · 全国工业废物资源化撮合平台

一个纯前端网页 Demo，解决工业废物回收里最麻烦的一环：**把「谁有废物」「谁能处理」「谁要再生料」三张互不相干的表，在全国范围内对上**。

关键前提：供给方在广东、加工厂在山东、需求方在浙江是常态。所以撮合不只是「匹配品类」，还要回答**跨省调运到底划不划算**。

打开方式：双击 `index.html`。没有依赖、不需要构建、不联网。

**多页结构**：6 个功能页各自是独立 HTML，点侧栏导航就是真实的浏览器跳转（URL 变化、前进/后退、可收藏）。公共 CSS / JS 抽到 `assets/` 下，三方登记数据用 `localStorage` 跨页共享，所以「在供给页登记 → 切到撮合页看到结果」这条链路是通的。

## 要解决的问题

废物回收是一条三段链路，任何一段断了，废物就只能进填埋场：

```
供给方                     加工厂                        需求方
工厂产生废物      →   分选 / 破碎 / 熔炼      →   买再生料做新产品
"东莞 480 吨废塑料"   "东莞收废塑料，出再生塑料粒子 75%"   "宁波要 500 吨再生塑料粒子"
```

难点有两个：

**第一，三方的描述口径完全不同。** 供给方说**废物品类**，需求方说**产品品类**，中间没有天然对应。加工厂是那个翻译器——所以平台强制要求加工厂同时登记「能吃什么」和「能产出什么、收率多少」，用收率把废物量折算成再生品量。

**第二，全国范围内，地理距离变成了硬约束。** 江西的废纸拉到山东，1,181 公里运费就是 433 元/吨，占处置费的 37%。平台必须把物流成本算进撮合决策，而不是只做品类匹配。

## 撮合算法

### 分配流程

对每一条废物供给，按顺序执行：

1. **筛品类** —— 过滤出 `accepts` 包含该废物品类的加工厂（全国范围）
2. **打分排序** —— 按五维匹配度排序，优先就近消纳
3. **扣产能** —— 用 `cap - load` 算剩余产能，吃不完就分给下一家
4. **按收率折算** —— `产出量 = 承接量 × ratio`，一家厂可能产出多种再生品
5. **匹配需求** —— 拿每个产出物去找 `type` 一致的需求方，按**到厂净价**排序分配

### 匹配度打分（满分 100）

| 维度 | 权重 | 说明 |
|---|---|---|
| 品类匹配 | 35 | `accepts` 命中的基础分 |
| 产能满足 | 14 | 剩余产能占待处理量的比例 |
| 产出被吸收 | 25 | 再生品中有多少被需求方认领 |
| 物流经济性 | 18 | `1/(1+km/400)`，0km→1.0 / 400km→0.5 / 1200km→0.25 |
| 加工厂评级 | 8 | 平台评分 / 5 |

**物流权重刻意给高。** 产能权重如果压过物流，南昌的废纸会被 1,100 公里外的山东大厂抢走——因为那家厂余量大——结果运费吃掉全部收益。就近消纳应该优先于「找大厂」。

### 两段物流

这是全国撮合区别于同城撮合的核心。废物要运两次：

```
段① 收运：供给方 ──→ 加工厂        （废物入场）
段② 配送：加工厂 ──→ 需求方        （再生品出厂）
```

- 运费单价 = `距离 × 0.35 元/吨·公里 + 20 元/吨装卸短驳`
- 距离用城市经纬度算直线距离，再乘 1.25 公路绕行系数；同城按 25km 计
- 两段运费都计入链路的物流成本

**需求方排序用的是「到厂净价」而不是报价本身**：`netPrice = 需求方报价 − 配送运费`。否则报价高但远在天边的买家会把就近的买家挤掉——实测这一条能把平均配送距离从 617km 压到 297km，物流成本从 161 万降到 99 万。

### 三种结果状态

- **链路闭环** —— 废物全部被承接，产出物全部被吸收
- **部分匹配** —— 只承接了一部分，或产出物有剩余
- **匹配失败** —— 全国范围内都没有加工厂能接收该品类

## 功能页面

### 平台总览
- 4 个 KPI：全国覆盖省份数、撮合消纳量、跨省联动量、物流成本
- **区域供需缺口 · 按省份**：本省废物产出量 vs 本省加工余量，缺口即为需要跨省调出的量
- **跨省流向 TOP**：只列真正跨省的链路，标注流向与里程
- 加工厂产能利用率 TOP10、链路缺口诊断（含「省际产能错配」专项）

### 智能撮合
- 顶部四段漏斗：废物入池 → 撮合消纳 → 再生品产出 → 物流成本
- 每条结果一张卡片，画成 `供给方 → 加工厂 → 再生品 → 需求方` 四段链路
- 每个节点标注省份·城市，跨省节点用橙色标签标出
- 供给方节点显示**收运距离与运费**，需求方节点显示**配送距离与运费**
- 支持「全部 / 仅跨省 / 仅省内」筛选、匹配度阈值过滤、导出 CSV（25 列，含两段物流明细）

### 区域联动
- **大区联动矩阵**：行 = 废物产出大区，列 = 加工消纳大区。跨大区流量远小于大区内自消纳，所以用**独立色阶**，否则跨区格子几乎看不见
- **省内 / 跨省结构**：环形图 + 废物流与再生品流的双向统计
- **省份供需台账**：废物产出 / 加工余量 / 再生品需求 / 跨省调出 / 跨省调入 / 供需状态
- **跨省链路明细**：逐条列出跨省链路的运量、里程、单位运费、收运运费、匹配度

### 三方登记
| 页面 | 登记内容 | 关键字段 |
|---|---|---|
| 供给方 | 废物从哪来、有多少、想付多少处置费 | 废物类型、月产出量、**省份 + 城市**、期望处置单价 |
| 加工厂 | 能吃什么、还剩多少产能、能产出什么 | 可接收类型（多选）、处理能力、已占用、**产出物 + 收率**、省份 + 城市 |
| 需求方 | 要什么再生料、要多少、能出多少钱 | 需求产品类型、月需求量、可接受单价、省份 + 城市 |

提交后立即全国重新撮合。需求表还会区分「无货源」与「出价偏低」——后者说明平台有货，只是被出价更高的买家拿走了。

### 数据里的几个设计意图

- **武汉 350 吨餐厨垃圾撮合失败** —— 华中地区完全没有餐厨处置能力，全国也没有富余产能。这是「招商建产能」的信号，不是调运能解决的问题。
- **江西南昌的废纸跨省到山东** —— 南昌本地只有 80 吨富余产能，剩下 240 吨必须外流，1,181 km、运费 ¥433/吨，占处置费的 37%。
- **广东东莞的废塑料大部分本地消化，60 吨跨省到浙江** —— 本地产能 420 吨不够 480 吨的供给，溢出部分才外流。
- **产能利用率普遍打满（平均 93%）** —— 这是跨省调运大量发生的根本原因。
- **武汉铜业再生铜 0% 满足** —— 平台有 108.6 吨产出，但它出价 ¥61,500 低于无锡的 ¥62,000，差额不够覆盖多出来的运费。页面会标成「出价偏低」而非「无货源」。

改数据有两种方式：页面上点「重置演示数据」恢复初始状态（同时清空浏览器里存的登记数据），或直接改 `assets/app.js` 里的 `SEED` 对象。

## 数据结构

```js
// 城市经纬度（用于估算公路里程，非测绘数据）
const CITY = { '东莞':[23.02,113.75], '潍坊':[36.71,119.16], ... };

// 省份 → 经济大区
const PROVINCE_REGION = { '广东':'华南', '山东':'华东', ... };

// 供给方
{ id, company, province, city, type, qty, price }

// 加工厂 —— outputs 是撮合的关键
{ id, name, province, city, rating, accepts: ['废塑料'], cap, load,
  outputs: [{ type: '再生塑料粒子', ratio: 0.75 }, { type: '塑料碎片', ratio: 0.12 }] }

// 需求方
{ id, company, province, city, type, qty, price }
```

`ratio`（收率）表示每吨废物能产出多少吨该再生品，取值 0~1。同一家加工厂可以有多个产出物，收率之和不要求等于 1（残渣、损耗不计入）。

**两条硬性约束**：
1. 加工厂 `outputs[].type` 必须与需求方 `type` 字符串完全一致才能匹配。这是有意为之——迫使双方用同一套再生品命名。
2. `city` 必须能被 `CITY` 表查到，否则距离按默认 600km 估算。

## 技术实现

- **多页静态站**：6 个 HTML 页面 + 共享 `assets/app.css`（约 300 行）+ `assets/app.js`（约 1,550 行）。零外部依赖，无 CDN、无框架、无图表库、无构建步骤
- **导航是真实链接**：侧栏与移动端胶囊导航都是 `<a href="xxx.html">`，当前页由 `<body data-page="xxx">` 标出，品牌名也可点回总览
- **公共外壳注入**：侧栏 / 顶栏 / 移动端导航的标记由 `buildShell()` 按 `NAV` 数组统一生成，6 个页面不重复维护同一份结构
- **状态与持久化**：三方登记写入 `localStorage`（键 `looplink.state.v1`）；每次进入任意页面都 `computeMatches()` 重算一遍，保证 6 个页面读到同一份撮合结果。隐私模式下 localStorage 不可用时静默降级为页内内存态
- **按页渲染**：每个 `renderXxx()` 开头都有 `if (!$('#容器')) return;` 守卫，所以在任意页面调用 `renderAll()` 都安全，只有属于本页的区块会渲染
- **地图**：刻意不使用地理轮廓图。区域分析用矩阵表、条形图、流向列表表达，避免引入地图数据合规问题
- **图表**：全部手写 —— 条形图用 CSS 宽度百分比，匹配度圆环与占比环形图用 SVG `stroke-dasharray`，大区矩阵用带透明度的表格单元格
- **响应式**：≤860px 隐藏侧栏，切换为顶部横向胶囊导航；链路卡片自动转为纵向堆叠；宽表格在容器内横向滚动
- **碳减排估算**：按品类设定减排因子（废金属 9.5、电子废弃物 5.5、废旧锂电池 4.8、废纸 1.8 等 tCO₂e/吨），乘以撮合量

浏览器兼容：Chrome / Edge / Safari 现代版本。

## 已知限制

这些是 Demo 的刻意取舍，上生产前需要替换：

1. **撮合是贪心的，不是全局最优**
   按供给登记顺序逐条分配，先登记的废物优先占产能。真实场景需要建整数规划模型（OR-Tools / 匈牙利算法），以「物流成本 + 处置成本 − 再生品收益」为目标函数求解。

2. **省份级缺口是宏观指标，不等于品类级平衡**
   广东全省废物产出 1,180 吨、加工余量 1,170 吨，看总量几乎平衡；但废塑料产能不足、废金属有富余，实际仍产生 90 吨跨省调运。总览页对这一条有明确提示。

3. **距离用城市中心点坐标估算**
   `CITY` 表存的是城市中心点经纬度，直线距离 × 1.25 当作公路里程，没有路网、没有实际路径规划。误差在 10~20% 量级。

4. **运费单价是单一费率**
   统一按 0.35 元/吨·公里 + 20 元/吨装卸，没有区分车型、吨位、是否危废、是否冷链、整车/零担。

5. **没有考虑时间维度**
   所有数据按「吨/月」静态处理，没有库存、没有提货周期、没有合同周期。

6. **没有真实性校验**
   谁都能登记任意产能，平台没有资质核验、没有危废经营许可证校验。跨省转移危险废物在现实中需要审批与转移联单，Demo 未建模。

7. **数据只存在浏览器本地**
   三方登记写入 `localStorage`，换浏览器 / 清缓存即丢失，也无法多人协同。接入后端需要用户体系 + 四张业务表（三方 + 撮合结果快照）。

8. **碳减排因子是行业经验值**
   不是按具体工艺和区域电网排放因子测算的，仅用于展示量级。

| `icon-192.png` `icon-512.png` | PWA 图标 |
| `icon-maskable-512.png` | PWA 自适应图标（Android 遮罩用） |
| `site.webmanifest` | PWA 清单：名称、主题色、图标声明 |
| `assets/brand/looplink-mark.svg` | 源：带底板的精致版（≥48px） |
| `assets/brand/looplink-mark-small.svg` | 源：带底板的加粗版（16 / 32px） |
| `assets/brand/looplink-mark-flat.svg` | 源：无圆角全出血版（iOS / 遮罩复用） |
| `assets/brand/looplink-mark-mono.svg` | 源：白色单色标，用于渐变底板之上 |
| `assets/brand/icon-preview.html` | 预览页：标签栏明暗底色、各尺寸实物、遮罩安全区 |
| `assets/brand/build-icons.cjs` | 生成器：源 SVG → 根目录全部图标 + manifest |

### 三档几何，不是一个图标缩三次

同一个图形在小尺寸和大尺寸下要的东西不一样，所以按像素分了档（源见 `build-icons.cjs` 的 `GEOM`；坐标都在 512 栅格上）：

| 档位 | 几何 | 用在 | 为什么 |
|---|---|---|---|
| `bold` 加粗版 | `r:96 sw:54`，**无**交叉断口 | `favicon.svg`、16 / 32 px PNG、`.ico` 的 16 / 32 | 16px 下只占 3px 半径、1.7px 描边，细描边会糊成色块；断口也会让环看着「破」了 |
| `fine` 精致版 | `r:92 sw:42`，**带**「上压下」断口 | `favicon-48`、`icon-192`、`icon-512`、`.ico` 的 48 | 看得清细节了，断口让两环真正「扣」起来，而不是叠在一起 |
| `flat + 安全区` | 全出血 + 图形缩到中心 80% | `apple-touch-icon`、`icon-maskable-512` | 见下 |

断口的做法是给左下环套一层 mask，mask 里用**加宽 1.6 倍**的右环描边挖洞——比手算交点省事，也不会在交叉处留下接缝。

### 两个平台规则

- **iOS 自己裁圆角**，所以给它**无圆角、全出血**的方图（`looplink-mark-flat.svg`）。如果给它一张自己已经带圆角的图，iOS 会在圆角外面再切一层，出现白边或缺口。
- **Android 自适应图标会被厂商遮罩裁成各种形状**（圆形、圆角方、水滴…），所以图形必须收在中心 80% 安全区内，否则贴边内容会被切掉。这一档的图形是等比缩到 74% 再居中。

顺带说明：**带底板图标的圆角取 22.7%**（512 → `rx:116`），这是 iOS 应用图标的惯例比例；**侧栏那块 36px 底板沿用站内的 11px 圆角**（约 30%），是为了跟导航项（10px）、卡片（14px）凑成一套 UI 圆角语言，不跟图标硬对齐。

### 改图标

源文件就是 `assets/brand/` 下的四个 SVG，改完重新出图：

```bash
npm i @resvg/resvg-js --no-save   # 只用到 SVG→PNG 渲染，不进依赖清单
node assets/brand/build-icons.cjs
```

脚本会把根目录的 `favicon*` / `icon-*` / `apple-touch-icon.png` / `site.webmanifest` 全部重写一遍（`site.webmanifest` 也由脚本生成，别手改）。侧栏那个内联 SVG 在 `assets/app.js` 的 `buildShell()` 里，几何与 `bold` 档同源——24 栅格下的 `r:4.5 sw:2.531 cx:8.25/15.75`，正是 512 栅格 `÷ 24 × 512 = 21.333` 换算过来的，改完记得两边一起改。

不用命令行也行：`assets/brand/icon-preview.html` 是预览页，双击打开就能看标签栏明暗两种底色下的真实 16px 效果、各尺寸实物、以及遮罩安全区示意。

> 注：`legacy/index.spa.html` 是封存的旧版快照，它的品牌标**有意保持原样**（便于对比），只有 `<head>` 里的图标引用跟着更新了。
